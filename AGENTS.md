# azure-devops-extensions

Several Azure DevOps extensions, one top-level folder each. **Each folder is an independent npm
project** with its own `package.json`, lockfile, `tools/` and `AGENTS.md`, so read that one
before working inside it. npm workspaces cannot nest, which is why there is no root workspace.
Run npm commands from inside the extension's folder.

## Layout

- `<extension>/`: the extension's npm project.
- `.github/workflows/<short>-ci.yml` and `<short>-publish.yml`: one pair per extension. They
  are path-filtered to the extension's folder and run with it as their working directory.
- `Taskfile.yml`: `task pre-commit` runs every extension's checks. Run it before every commit.

## Releases and identity

- Release tags are `<short>-v<version>` (`pi-v1.0.1`), never a bare `v*`: a bare tag cannot
  say which extension it releases. They are pushed after the release is live and start no
  workflow. The whole process is in `RELEASING.md`.
- Marketplace identity is `{publisher}.{id}`. Changing either one creates a different
  extension with no upgrade path. Each extension's own `AGENTS.md` says where its publisher
  comes from.

## Fixtures

Fixtures are synthetic, or scrubbed captures whose names are fictitious (`contoso`, `Platform`,
`alpha`, and so on). No real organisation, project, pipeline, resource or person's name
belongs in any file or commit message. Pipeline Insights' fixtures are a synthetic estate
generated by `core/fixtures/contoso.ts`.
